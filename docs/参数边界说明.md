# UnifiedOFTWorkflow 参数边界说明

这份文档说明三件事：

1. 哪些内容是写死在代码逻辑里的
2. 哪些内容是在部署后由 owner 配置进去的
3. 哪些内容是每次调用时才传入的

对应合约：
- `src/examples/UnifiedOFTWorkflow.sol`

## 一、写死在代码里的内容

这些内容不是你以后换链、换币时去改的，而是这份合约本身的工作方式。

- 合约同时支持两种流程
  - `swapAndBridge(...)`
  - `swapReceivedOFT(...)`
- 权限模型
  - `owner`
  - `approvedCallers`
  - `approvedSwapAdapters`
  - `approvedBridgeAdapters`
- 安全逻辑
  - `ReentrancyGuard`
  - `rescueTokens`
  - `rescueNative`
- 事件结构
  - `SourceRouteUpdated`
  - `DestinationRouteUpdated`
  - `SourceSwapAndBridgeExecuted`
  - `DestinationSwapExecuted`

简单说：

这部分是“合约怎么工作”的定义，不是“某条业务路线长什么样”的定义。

## 二、部署后由 owner 配置进去的内容

这部分是“路线配置”。它们不是每次交易都变化的，所以不应该让调用方每次都传。

### 1. 源链路线 `SourceRouteConfig`

字段：

- `tokenIn`
  - 含义：源链用户拿来输入的代币地址
  - 例子：USDT、USDC

- `oftToken`
  - 含义：源链 swap 之后、准备用 LayerZero 跨链发送的 OFT 代币地址
  - 例子：HANDL、APR

- `swapAdapter`
  - 含义：源链所使用的 swap 适配器地址
  - 作用：负责把 `tokenIn -> oftToken`

- `bridgeAdapter`
  - 含义：源链所使用的 LayerZero/OFT 桥接适配器地址
  - 作用：负责把 `oftToken` 发到目标链

- `dstEid`
  - 含义：目标链对应的 LayerZero endpoint id
  - 作用：告诉桥要发到哪条链

- `enabled`
  - 含义：这条路线是否启用
  - `true` 表示可用
  - `false` 表示禁用

### 2. 目标链路线 `DestinationRouteConfig`

字段：

- `oftToken`
  - 含义：目标链上收到的 OFT 代币地址
  - 例子：Base 上的 HANDL、BSC 上的 APR OFT

- `payoutToken`
  - 含义：目标链最后要换出的目标代币地址
  - 例子：USDC、USDT

- `swapAdapter`
  - 含义：目标链所使用的 swap 适配器地址
  - 作用：负责把 `oftToken -> payoutToken`

- `enabled`
  - 含义：这条目标链路线是否启用

### 3. 白名单配置

这些也是 owner 预先配好的，不是每次调用时传。

- `approvedCallers`
  - 含义：哪些地址有权调用主流程
  - 适合放 bot、EOA、你的执行器地址

- `approvedSwapAdapters`
  - 含义：哪些 swap adapter 是可信的、允许被使用

- `approvedBridgeAdapters`
  - 含义：哪些 bridge adapter 是可信的、允许被使用

## 三、每次调用时才传入的内容

这部分是“交易本次执行信息”，它们天然会变，所以应该在调用时传。

### 1. 源链调用 `swapAndBridge(...)`

字段：

- `routeId`
  - 含义：要走哪一条已经注册好的源链路线
  - 本质：路线编号

- `amountIn`
  - 含义：本次要投入多少 `tokenIn`

- `minBridgeAmount`
  - 含义：本次最少要换到多少 `oftToken`
  - 作用：做滑点保护

- `recipient`
  - 含义：目标链接收 OFT 的地址
  - 类型是 `bytes32`
  - 本质上就是目标链收款地址的跨链表示形式

- `sourceSwapData`
  - 含义：源链 swap 需要的额外参数
  - 例子：path、pool 信息、router calldata

- `bridgeOptions`
  - 含义：LayerZero 的执行参数
  - 例子：目标链 gas 设置之类的参数

- `composeMsg`
  - 含义：跨链时附带的额外消息
  - 如果不用自动执行，通常可以为空

- `msg.value`
  - 含义：支付 LayerZero 原生手续费

### 2. 目标链调用 `swapReceivedOFT(...)`

字段：

- `routeId`
  - 含义：要走哪一条已经注册好的目标链路线

- `oftAmountIn`
  - 含义：本次要卖出多少 OFT

- `minAmountOut`
  - 含义：本次最少要换出多少目标代币
  - 作用：做滑点保护

- `recipient`
  - 含义：目标代币最终发给谁

- `destinationSwapData`
  - 含义：目标链 swap 需要的额外参数
  - 例子：path、pool 信息、router calldata

## 四、为什么这样分层

这样分层的好处是：

- 不会把本来固定的业务路线信息，变成每次都要重复传的参数
- 不会让调用方随手传一个陌生 adapter 地址进来执行
- 后面新增链和币种时，通常只是“新增 route”，不是改主逻辑

换句话说：

- 路线信息：预先配置
- 交易信息：调用时传

## 五、你以后如果要给我新的链和代币

我通常需要你提供：

1. 源链名称
2. 目标链名称
3. `tokenIn` 地址
4. `oftToken` 地址
5. `payoutToken` 地址
6. 源链交易 hash
7. 目标链交易 hash

如果有这些信息，我就能更快判断：

- 哪些字段应该写进 `SourceRouteConfig`
- 哪些字段应该写进 `DestinationRouteConfig`
- 哪些 calldata 需要调用时传

## 六、当前最重要的一句话

这份合约不是“把所有地址都当参数传进来”。

而是：

- 路线相关地址：owner 预先配置
- 本次交易相关参数：调用时传

这就是现在这版 `UnifiedOFTWorkflow` 的边界。
